Architecture

Big teacher. Small student. Plain C.

How a 4B decider's judgement ends up in a few KB of firmware.

  • Distillation
  • nano
  • pico
  • On the chip
  • Runtimes

Taught by a full Strands Decider

A full Strands Decider (4B) teaches the text tiers through distillation on ~430k decisions. The students keep the same question shapes, so a schema written for Strands Decider works here.

Static embeddings that can read a number

nano uses static embeddings over a pruned 8-16k vocabulary at 128 dimensions. Key-value number pooling reads battery: 6% as a value, so sensor readings in text are not just tokens.

A compiler, not a model download

You write a spec: sensors, rules and questions. The public Strands Decider 2B labels sampled states. The compiler writes one tiny MLP per question as C. Your firmware includes the header and calls a function.

{
  "name": "greenhouse",
  "context": "open vents when it is above 30 C; water when soil moisture is below 25%; never water and vent at the same time in frost.",
  "features": [
    {"name": "temp_c",        "type": "number", "min": -10, "max": 50},
    {"name": "soil_moisture", "type": "number", "min": 0,   "max": 100, "unit": "%"},
    {"name": "raining",       "type": "bool"},
    {"name": "time_of_day",   "type": "enum", "values": ["night", "morning", "afternoon", "evening"]}
  ],
  "questions": {
    "action":   {"type": "choice", "instructions": "What should the controller do now?",
                 "criteria": {"nothing": "no change", "water": "start watering",

    "alert":    {"type": "noul", "instructions": "Should the grower be alerted?"},
    "stress":   {"type": "score", "instructions": "How stressed are the plants?",
                 "criteria": ["fine", "mild", "severe"]}
  }
}
firmware/main.c
#include "sparrow_pico_greenhouse.h"

float p[GREENHOUSE_ACTION_N];
greenhouse_action(&s, p);                  /* probabilities over the options */

Built for the ESP32-S3

int8 SIMD on the vector unit through the ESP-NN kernel, with weights in PSRAM or internal RAM. The C99 runtime has no malloc and reads the model from flash.

  1. Your firmware

    app_main() · sparrow_choice(...)

  2. sparrow C99 runtime

    no malloc · model read from flash

  3. int8 SIMD kernels

    ESP-NN on the vector unit

  4. Memory placement

    weights in PSRAM / internal RAM

  5. ESP32-S3

    240 MHz · 16 MB flash · 8 MB PSRAM

ESP32-S3 (QFN56 rev0.2), 240 MHz, 16 MB flash, 8 MB PSRAM

The C runtime matches the Python runtime to within 1e-5 on the host; on the ESP32-S3, int8 builds agree with the host on 150-155 of 155 decisions.
