Use it

Small questions. Calibrated answers.

Most decisions in an agent or a robot have a short list of answers. Sparrow answers them about a state you give it, with calibrated probabilities, in the same shapes as Strands Decider.

  • Yes / no noul

    "Is the user upset?" A probability you can threshold.

  • Pick one choice

    "Which skill should run?" A choice from your list, with a probability for each option.

  • Score score

    "How urgent is this?" A rating on the scale you define.

triage.py
from sparrow_decider import Decider

d = Decider.load()   # bundled nano model

tools = {
    "flights":  "search and book flights",
    "refunds":  "refund a payment",
    "weather":  "forecasts for a city",
    "calendar": "create or move meetings",
}
answer = d.ask(
    "User: I was charged twice, I want my money back",
    {"tool": {"type": "choice",
              "instructions": "Which tool fits?",
              "criteria": tools}},
)["tool"]
print(answer["choice"], answer["confidence"])
# refunds 0.97

C library guide →
main/app_main.c
#include "sparrow.h"

extern const uint8_t model_start[] asm("_binary_model_spb_start");
extern const uint8_t model_end[]   asm("_binary_model_spb_end");
static sparrow_model model;
static sparrow_ctx ctx;

void app_main(void) {
    sparrow_load(&model, model_start, model_end - model_start);
    sparrow_option opts[] = {{"pick", "pick up an object"}, {"navigate", "move somewhere"},
                             {"speak", "answer the person"}};
    float conf;
    int k = sparrow_choice(&model, &ctx, "operator: bring me the red mug", "Which skill?", opts, 3, &conf);
}

Choosing

pico or nano?

nano reads text and answers any question you pose at runtime. pico has no text and no vocabulary: you describe your device's sensors and questions, and get C.

Many devices use both: pico in the control loop, nano for anything said or written.

On the chip

Same $10 board. Much faster.

On the ESP32-S3: int8 SIMD on the vector unit (ESP-NN kernel), weights in PSRAM / internal RAM.

Parity

The C runtime matches the Python runtime to within 1e-5 on the host; on the ESP32-S3, int8 builds agree with the host on 150-155 of 155 decisions.

Python

pip install sparrow-decider. numpy only.

C99

No malloc, model read from flash. Ships as an ESP-IDF component.

sparrow-pico compiler

Write a device spec, get a C header.

Honest limits

What it is not.

Sparrow is for fixed-answer decisions about a known kind of state. We publish the misses next to the wins.

Open-ended language it never trained on: well behind the 2B (MASSIVE domain routing 0.37-0.67 across released Sparrow models vs 0.86).

Yes/no judgement on JevBench is near chance at every tier.

pico answers only the questions it was compiled for.

A pico model is as good as its teacher on your spec, and no better. Never use a learned model as the only safety stop.

Keep an LLM or a full decider for open-ended reasoning. Use confidence to fall back to it.
